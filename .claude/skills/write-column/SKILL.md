# write-column

バスケットボールの用語・戦術・基本の動き記事を `column/` に執筆する。

## 呼び出し方

```
/write-column <トピック>
```

トピックを省略した場合は、既存記事と重複しない候補を複数提案し、ユーザーの選択を待つ。

---

## 実行手順

### Step 1: 既存記事の確認（重複排除）

`column/` ディレクトリ内の全 `.md` ファイルを読む（`sample-article.md` は除く）。
各記事の `title` と主要トピックを把握し、以下のことを判断する：

- ユーザーが指定したトピックが既存記事と実質的に重複していないか
- トピックが省略された場合は、カバーされていないトピックの候補を複数提案する

**重複する場合はアラートで執筆を停止し、別のトピックを提案すること。**

### Step 2: テンプレートの参照

`column/sample-article.md` を読み込む。そのフロントマターの全キーと本文の構成（見出し構成・特殊ボックスの書き方）を記事の型として適用する。

### Step 3: ファイル名と permalink の決定

- ファイル名: 英語の slug 形式（半角英数字とハイフンのみ）で命名する
  - 例: トピックが「ピック&ロール」→ `pick-and-roll.md`
- permalink: `/column/<slug>/`（ファイル名の slug と一致させる）
- 既存ファイル名と衝突しないことを確認する

### Step 4: フロントマターの生成

`sample-article.md` と同じキー構成で生成する。各キーの規則は以下の通り：

| キー | 規則 |
|---|---|
| `layout` | `column` |
| `title` | 記事の題目。約30文字以内。検索で見つかりやすい表現にする |
| `description` | 約120文字の説明文。検索結果に表示される |
| `date` | 今日の日付（`YYYY-MM-DD`） |
| `update` | 今日の日付（`YYYY-MM-DD`） |
| `author` | `StatsToo編集部` |
| `category` | 記事の内容で自動分類する。分類基準は下記 |
| `tags` | 5件以内。`バスケットボール` を必須とし、記事の内容に合わせて追加 |
| `thumbnail` | `/image/column/<slug>.jpg` |
| `excerpt` | 50〜100文字の冒頭要約。一覧ページに表示される |
| `toc` | `true` |
| `permalink` | `/column/<slug>/` |

**カテゴリー分類基準：**

| カテゴリー | 該当トピック例 |
|---|---|
| `戦術` | ピック&ロール、スクリーン、フォーメーション、チームプレーなど戦術・戦略系 |
| `練習` | シュート動作、ボールハンドリング、パス技法など個人スキル習得系 |
| `ルール` | ゲーム規則、バイオレーション、反則など規則解説系 |
| `用具` | シューズ、ボール、アプリなどツール・用具系 |

### Step 5: 本文の執筆

以下のガイドラインに従って執筆する：

1. **導入文（リード文）**: 読者の悩みに寄り添い、この記事で何がわかるかを簡潔に伝える。2〜3行で構成する
2. **「〇〇とは？」定義セクション**: 用語や概念の定義を冒頭で説明する（初心者向け対応）
3. **H2見出し**: 主要トピックを3〜5つ設定する（見出しの最初は必ず H2）
4. **H3小見出し**: 必要に応じて細分化する
5. **特殊ボックス**: 記事には少なくとも2つ以上の特殊ボックスを使用する
   - `.note`（青色）: 豆知識や補足情報
   - `.point`（緑色）: 特に重要なポイント
   - `.warning`（オレンジ色）: 注意点や間違いやすいこと
   - 書き法は以下の通りで、`sample-article.md` の形式を faithfully に再現する:

```html
<div class="note">
💡 <strong>補足情報</strong><br>
ここに補足情報を書く。
</div>

<div class="point">
✅ <strong>ポイント</strong><br>
ここに重要なポイントを書く。
</div>

<div class="warning">
⚠️ <strong>注意</strong><br>
ここに注意点を書く。
</div>
```

6. **よくある質問セクション**: `## よくある質問（FAQ）` を置き、`### 質問文？` の H3 と、その直下に2〜4行の回答を3件前後書く
   - `_plugins/faq_schema.rb` がこのセクションを解析し、FAQPage の構造化データを自動生成する（本文に書いた内容がそのまま構造化データになるため、本文に無いQ&Aを構造化データだけに書いてはいけない）
   - 質問は検索で実際に打ち込まれる形（例:「〜は反則になりますか？」）にする
7. **まとめセクション**: `## まとめ` で番号付きリストに3つのポイントをまとめる
   - `_plugins/key_points.rb` がこの箇条書きを抽出し、記事冒頭の「この記事の要点」ブロックとして表示する。**必ず番号付きリストで書くこと**（この形式を崩すと冒頭の要点ブロックが出力されない）
   - 各項目は `**見出し**: 説明` の形式で、単体で読んでも意味が通る一文にする
8. **末尾の誘導文**: まとめの後に以下の文を配置する:
   `ぜひStatsTooのツールを使って、バスケットボールの上達に役立ててください！`

### Step 6: ファイルの書き込みと報告

記事を `column/<slug>.md` に書き込む。
書き込み後は以下を報告する：

- 作成したファイルパス
- 記事の見出し構成（H2一覧）
- `thumbnail` 画像（`/image/column/<slug>.jpg`）が別途用意で必要であること
